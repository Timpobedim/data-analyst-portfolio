# 01 — Аналитик данных

Восемь исследований на открытых данных. Каждое отвечает на один вопрос бизнеса, каждое пересобирается одной командой, и в каждом есть раздел «чего это не доказывает».

| Проект | Вопрос | Метод | Главное число |
|---|---|---|---|
| [01 — скоринг рассрочки](проекты/01-скоринг-рассрочки) | какие признаки связаны с просрочкой? | хи-квадрат, V Крамера, поправка Холма | просрочка 8,4%, значимы 2 гипотезы из 4 |
| [02 — аренда квартир](проекты/02-аренда-квартир) | что влияет на цену аренды? | межквартильный размах, Спирмен, Манна–Уитни | связь площади и цены 0,86 |
| [03 — тарифы каршеринга](проекты/03-тарифы-каршеринга) | какой тариф выгоднее? | Левен, Стьюдент или Уэлч, доверительные интервалы | +1 671 ₽ на пользователя, d = 1,66 |
| [04 — рынок настольных игр](проекты/04-рынок-настольных-игр) | какие жанры растут? | выбор актуального периода, Спирмен | семейные игры — 50,8% тиража |

| [06 — воронка онлайн-школы](проекты/06-воронка-онлайн-школы) | где теряются ученики и какой канал окупается? | конверсия по шагам, Холм, окупаемость | до регистрации доходит 13,2% |
| [07 — отток автосервиса](проекты/07-отток-автосервиса) | кому слать скидку? | логистическая регрессия и лес, порог из цены ошибки | ROC-AUC 0,757 при оттоке 18,9% |

## Общее решение: исследование, которое можно проверить

Всё в этой папке устроено вокруг одного требования: читатель должен иметь возможность повторить расчёт и увидеть те же числа.

- **Данные создаёт код, а не тренажёр.** У каждого исследования свой генератор с зафиксированным зерном; набор сохраняется рядом с отчётом в CSV с точкой с запятой и меткой кодировки — чтобы открывался в русском Excel без плясок. Данные намеренно грязные: пропуски, дубли, ошибки ввода.
- **Отчёт собирается командой.** `analiz all` пересобирает все восемь отчётов за 12 секунд. «Забыть перезапустить ячейку» здесь нельзя.
- **Графики — отдельные файлы SVG.** Отчёт весит килобайты, картинки читаемы в системе контроля версий и не размываются при увеличении.
- **Расчёты покрыты тестами.** 70 проверок: критерии, поправки, доверительные интервалы, подготовка данных, воспроизводимость и сами исследования.

## Сквозные приёмы

- **Рядом с каждым p-значением — размер эффекта и доверительный интервал.** При выборке в сто тысяч строк значимым становится любое различие; без величины эффекта вывод «различие есть» ничего не стоит.
- **Поправка Холма там, где гипотез несколько.** В скоринге из четырёх гипотез после поправки остаются две, в воронке сравнение каналов идёт с поправкой на четыре сравнения.
- **Размер выборки считается до эксперимента.** В A/B-тесте прямо сказано, хватает ли данных, чтобы заметить ожидаемый прирост, — иначе «различий не обнаружено» не значит ничего.
- **Проблема подглядывания показана, а не упомянута.** p-значение посчитано по накопленным данным на каждый день теста: видно, как оно ныряет ниже 0,05 и возвращается.
- **У модели есть опорный ответ и цена ошибки.** В задаче об оттоке точность 81% сравнивается с ответом «никто не уйдёт», а порог решения считается из стоимости скидки и стоимости потерянного клиента, а не берётся 0,5.
- **Утечка целевой переменной названа вслух.** Признак, который знает ответ заранее, исключён из модели, и в отчёте написано почему.
- **Медиана вместо среднего там, где данные скошены**, и явные границы выбросов вместо молчаливого удаления.
- **Раздел «чего это не доказывает» есть в каждом отчёте.** Без него аналитика читается увереннее, чем заслуживает.

## Как запустить

```bash
uv sync
uv run analiz list                 # какие есть исследования
uv run analiz run delivery_ab      # пересобрать одно
uv run analiz all                  # пересобрать все восемь
uv run analiz all --seed 7         # те же исследования на других данных
```

Результат каждого исследования — папка в `проекты/`: `README.md` с главным, `отчёт.md` целиком, исходные данные в CSV и графики в SVG.

## Как проверялось

- `ruff format`, `ruff check` (E, F, W, I, B, UP, S — bandit, C4, SIM, PT, RUF, DTZ) и `mypy --strict` с типами pandas (`pandas-stubs`) — без замечаний.
- `pytest` — 70 тестов за 33 с: критерии и их выбор (Левен → Стьюдент или Уэлч), поправка Холма, доверительные интервалы Уилсона, расчёт размера выборки, подготовка данных (дубли, пропуски, выбросы), генераторы и их воспроизводимость, формат отчёта, все восемь исследований целиком и командная строка.
- Отдельный тест проверяет воспроизводимость: одно зерно — тот же отчёт, другое зерно — другие числа.
- Все восемь отчётов в этой папке собраны командой `analiz all` и не правились руками.
- Числа в отчётах перепроверялись на правдоподобие: первая версия генератора давала окупаемость канала «+135 000%» и размер эффекта 3,5 стандартных отклонения — такие числа в портфолио выглядят как ошибка, и параметры были приведены к реалистичным.

### Не проверялось

- Данные синтетические. Все зависимости в них заложены генератором, поэтому выводы показывают метод, а не рынок: «площадь объясняет цену» здесь верно по построению.
- Настоящие открытые данные не использовались: у большинства российских источников нужно принимать условия использования, а часть из них закрыта для автоматической загрузки.
- Объёмы небольшие — от трёх до тридцати тысяч строк. Поведение на миллионах строк и время расчёта на них не проверялись.
- Машинное обучение представлено одной задачей и без перекрёстной проверки: для решения о внедрении её недостаточно.
- Дашборда нет: визуальная часть — статические графики. Интерактивные дашборды вынесены в специальность [05 — BI-аналитик](../05-bi-analyst).
- Отчёты проверены как текст: вёрстку Markdown в GitHub я не смотрел, браузер на этой машине для проверки недоступен.
